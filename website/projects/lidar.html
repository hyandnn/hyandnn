01 / The problem

A static representation meets a changing scene.

People and pets move through outdoor environments. Processing each observation in isolation loses the continuity needed to describe a moving target; a static scene representation alone can be insufficient.

The overall architecture had been selected before I joined. I implemented and maintained the system, and led the addition of tracking to extend its handling of dynamic targets.

02 / Method

A single observation describes what the sensor sees now. Tracking adds the question of which observations belong to the same target over time, supporting a continuous target state.

Robot motion changes the viewpoint and observation coordinates. Occlusion can remove returns temporarily without proving that a target has disappeared. These are reasons to interpret current observations together with motion context and temporal information.

03 / Engineering choices

Preserve height and temporal context.

An absent return is not a complete conclusion

The synthetic track shows a short occlusion and an illustrative continuation. It distinguishes current measurement from temporal inference; it does not prescribe the deployed tracker’s prediction policy.

A flat grid can hide relevant structure

I resolved deployment issues involving height information and overhanging obstacles. Outdoor scenes required care beyond a representation influenced by indoor two-dimensional grids.

04 / Result & boundaries

A targeted extension to an operating system.

I introduced tracking to address dynamic targets within the established framework. The contribution was integration and deployed-system engineering, rather than ownership of the original architecture.

LiDAR was the leading observation source in a multi-sensor system. Supporting sensors help interpret robot motion, but neither sensor context nor tracking removes all association ambiguity during occlusion.
