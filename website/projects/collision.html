03 / Physics simulation

Adding algorithm choices to a collision engine.

I extended an existing physics-simulation engine with collision-query capabilities, adapting established algorithms to its geometry types, interfaces and data flow.

MY ROLE

Broadphase, midphase and narrowphase algorithm integration.

CONTEXT

An existing physics-simulation engine.

Explore the concept · Physics simulationSynthetic illustration

Conceptual collision-query stages. Candidate bounds and illustrative convex shapes explain responsibilities rather than engine internals. All visuals are independently created conceptual illustrations using synthetic data. They do not show internal implementations, product recordings or measured research results.

01 / The problem

An algorithm has to fit the engine around it.

The engine offered a limited set of collision-query options. Extending it required connecting algorithm inputs and outputs to its own object representations and processing stages.

The additions complemented the original choices. They did not replace the complete collision system.

02 / Method

Three stages, three different questions.

  2. 02

    BVH · Midphase

    Relevant geometry regions

  3. 03

    GJK · Narrowphase

    Convex geometry query

Sweep and Prune belongs to the broadphase: spatial bounds and their overlap help identify candidate object pairs. Candidate filtering is not yet an exact contact determination.

A BVH midphase organizes finer geometry into hierarchical bounds so queries can restrict the region requiring further examination. GJK belongs to convex narrowphase queries, complementing existing algorithms including SAT.

03 / Engineering choices

Integration with preserved algorithm options.

Adapt the boundary between stages

The host engine and reference implementations handled basic geometry types and data flow differently. I adapted representations and query interfaces so the added algorithms could participate in the engine’s processing.

Add capabilities without discarding existing choices

Existing algorithms remained available. The engineering result was a wider set of selectable capabilities, not a claim that one algorithm universally outperforms the others.

04 / Result & boundaries

More capability, with distinct responsibilities.

The engine gained SAP, a BVH midphase and GJK as additional options. These were integrations of established algorithms; my contribution was implementation and adaptation within the host engine.

Broadphase candidates remain conservative approximations, and convex queries have geometric scope limits. The diagrams explain these responsibilities rather than replaying an internal engine execution.
