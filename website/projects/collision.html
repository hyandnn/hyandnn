03 / Physics simulation

Adding algorithm choices to a collision engine.

The challenge was to extend an existing physics-simulation engine with more collision-detection capabilities, while adapting to its types, interfaces and data flow.

MY ROLE

Integration of broadphase, midphase and narrowphase algorithm options.

CONTEXT

An existing, closed-source physics-simulation engine.

Conceptual sequence · Physics simulationIndependent synthetic illustration

01 / The problem

Geometry queries need a path through the engine.

The engine had a limited set of collision-detection options. Adding an algorithm required more than reproducing its mathematics: it had to work with the engine's own object representations and the way geometry moved between query stages.

Broadphase, midphase and narrowphase solve different parts of that task. A useful extension had to fit those responsibilities without discarding existing behavior.

02 / My contribution

Extend three stages, preserve existing options.

Broadphase · Sweep and Prune

I introduced SAP as an additional way to identify potential collision candidates from spatial bounds.

Midphase · Bounding volume hierarchy

I introduced a BVH midphase to organize geometry for subsequent collision queries.

Narrowphase · GJK

I integrated GJK alongside existing algorithms, including SAT, to expand convex-geometry query options.

Integration · Engine adaptation

I adapted the algorithms to the host engine's basic types, interfaces and data flow.

Representative outcome

Expanded the engine's algorithm options across collision-query stages while retaining the original choices.

03 / Engineering judgment

An established algorithm is still integration work.

These were integrations of established algorithms, rather than new algorithm inventions. The engineering contribution was making them usable within another engine's constraints.

The added capabilities complemented the original implementation. Keeping the existing options available avoided presenting the work as a wholesale replacement of the collision system.

The illustration shows candidate filtering, hierarchical bounds and convex queries as distinct concepts. It does not encode the internal engine's object model or implementation.

04 / Scope & limits

Capability, without invented benchmark claims.

The publicly described result is broader functionality. There is no published benchmark here establishing a particular speedup or accuracy improvement.

The host engine remains unnamed. This page explains the integration contribution without publishing its source, internal class definitions or architecture.

All demonstrations use synthetic data. Project descriptions are limited to publicly shareable responsibilities and conceptual explanations.
